# Alignment：先让画板服从设计系统，再开始实现

设计系统通常是从一批高保真画板里抽出来的。抽完以后如果画板没有回改，仓库里就同时存在两个"权威"：规则说 16，画板画的是 12 和 20。实现方无论跟哪一边都会被另一边判错；规则也只有组件内部的值，没有组件之间的距离；工具默认值（Penpot 行高 1.2）又让每个文字盒和 token 行高对不上。这个分支用来消掉这些矛盾，在任何页面实现开始之前完成。

触发条件：

- 新项目第一次落地设计系统（[land.md](land.md) 第 0 步）；
- 已有项目的设计系统是从画板抽出来的，但画板没有按它回改过；
- 屏幕验收（[screen-conformance.md](screen-conformance.md)）反复出现"代码对了、画板不对"的偏差。

## 1. 流程

```text
高保真画板 → 抽出设计系统 → 按设计系统回改画板 → 画板扫描门禁 → 开始实现
```

| 步骤 | 产出 | 完成标准 |
|---|---|---|
| 抽出设计系统 | 值规范（token）、几何契约、`components.md` 组件条目、`DS-PAGE-FLOW` 的分布统计 | 每个数值都有出处（画板名、版本） |
| 负责人定值 | `DS-PAGE-FLOW` 每种关系一个 token，例外表 | 每个 `owner` 行都有决策 id |
| 回改画板 | 设计文件新版本（改前、改后各存一个版本快照） | 改动只发生在画板上，规则不跟着画板走 |
| 扫描门禁 | 扫描记录：版本标签、规则来源 commit、每块画板的发现数 | 已批准画板 0 条表外发现 |
| 开始实现 | 页面任务 | 只对扫描干净的画板开工 |

## 2. 唯一权威方向

**规则定值和关系，画板只是规则的实例。** 规则 = 值规范 + 几何契约 + `components.md`（含 `DS-PAGE-FLOW` 和例外表）。画板展示规则产生的结果。

- 画板和规则不一致：改画板；或者由负责人改规则。不允许任何一方悄悄覆盖另一方。
- 规则一改，受影响的画板和设计文件里的主组件在**同一轮**跟着改，然后重新扫描。
- 代码只跟规则走。代码和画板不一致时，先问"画板是不是规则的正确实例"，扫描干净之后才按画板判代码。
- 这一条要在新项目落地时最先写进 `AGENTS.md`（[templates/agents-pointer.md](templates/agents-pointer.md)），并替换掉仓库里任何"画板是唯一来源"的旧表述。

和 [SKILL.md](SKILL.md) 的权威顺序不冲突：权威顺序管"代码和设计谁对"（设计对）；这里管"设计内部规则和画板谁对"（规则对）。

## 3. 几何契约

复制 [templates/geometry-contract.md](templates/geometry-contract.md) 到值规范。要点：

- 文字布局盒高度 = 字号 × token 行高；画板行高还不是 token 值时，按盒子中心比对，不按顶边。
- 图标盒取 token 尺寸，frame 即图标盒。
- 触控区向外扩，不占布局；只有无边框的单独图标按钮按 `touch-min` 见方画。
- 画板 y = 0 是安全区顶边，底边是系统导航区顶边；满宽、填满内容宽、包住内容三类元素各自列清。

上游扫描和下游屏幕比对共用这一份契约；两边任何一边改测量方式，都先改契约。

## 4. `DS-PAGE-FLOW`：组件之间的距离

复制 [templates/page-flow.md](templates/page-flow.md) 到 `components.md` §2。顺序：

1. 扫描全部已批准画板，统计每种关系的实际取值分布（扫描汇总的 `relations` 字段，每个值带出现次数和至多三个例子）。
2. 把分布交给负责人。负责人为每种关系选定一个 token；分布本身一致且符合 token 规范的可以直接标 `settled`。
3. 负责人决定保留的偏离登记为例外：规则、范围、值、理由、决策 id，并给范围写一条扫描测试。
4. 其余偏离在画板上改掉。

**取值是设计决定，agent 不得自行确定**，"取众数""取最接近的 token"也不行。agent 负责统计、列出矛盾、给出选项和影响面；选择由负责人做，并记进决策日志。

## 5. 画板扫描

工具在 [scripts/board-scan/](scripts/board-scan/)，只读，不改设计文件。

| 文件 | 作用 |
|---|---|
| `extract.penpot.js` | 在 Penpot plugin 上下文里运行，导出选定画板的扁平图层列表（几何相对画板） |
| `scan-core.mjs` | 纯函数：几何契约、图层规则（颜色、字体、行高、图标、栅格）、页面关系分类和比对、汇总 |
| `rules.mjs` | 读项目配置，并从项目自己的文档里解析 token 颜色、Relations 表和例外表 |
| `board-scan.mjs` | CLI：`build` 生成粘贴脚本，`scan` 离线扫描已保存的 extract（门禁退出码） |
| `board-scan.test.mjs` | 自带测试（`node --test`） |

项目相关的东西全部在配置里（schema：[schemas/scan-config.schema.json](schemas/scan-config.schema.json)，示例：[examples/board-scan/](examples/board-scan/)）：组件名前缀、资产和图标前缀、装饰图层规则、角色（顶栏、分节标题、列表行、固定底栏、浮层、面板、宫格）、行高阶梯、字体组合、栅格、`touch-min`、关系表和例外表的位置。值尽量用 `colorsFrom` / `flowFrom` / `exceptionsFrom` 从文档里读，扫描器自己不带任何值；文档一改，扫描就跟着改。

### 运行

```bash
node <skill>/scripts/board-scan/board-scan.mjs build --config <repo>/design/scan.config.json > /tmp/scan.js
```

1. 确认设计文件：配置里写了 `extract.fileName`，打开的文件不对时脚本直接报错。
2. 把 `/tmp/scan.js` 的内容交给 Penpot MCP `execute_code` 运行。返回汇总：`gate`（PASS / FAIL）、各规则总数、每块画板的发现（行高发现按字号折叠成计数）、关系分布。
3. `--board '<名字>'` 只扫一块画板；`--detail` 附上每条关系的测量值；`--raw` 返回 extract 本身，保存后可以用 `scan --extract <file>` 离线重扫，退出码 0 = PASS、1 = FAIL、2 = 配置错误。

### 先校准，再全量

扫描器对新项目一定有误报（装饰图层被算进盒子、浮层被当成页面内容、标题行没被识别……）。顺序：

1. 负责人指定 1～2 块认可的画板（"这块是对的"）。
2. 只扫这几块。每条发现逐条判：画板真错 → 记下，留到回改；扫描量错 → 改配置或扫描器，并加一条测试固定这个情形。
3. 认可画板上只剩真问题之后，再全量扫描。
4. 全量结果里，画板问题回改画板；负责人决定保留的登记为例外。**不得放宽规则或容差来消掉发现。**

### 门禁

- 页面任务开始前，它的已批准画板必须扫描干净（表外 0 条）。
- 改了已批准画板或主组件之后、改了任何规则（token、Relations 表、例外表）之后，重新扫描。
- 每次扫描写一份简短记录（放在项目约定的被 gitignore 的目录里）：设计文件版本标签、规则来源 commit、每块画板的发现数、改了什么、等负责人决定的是什么。值规范里只保留最近一次扫描干净的版本。

### 不检查的

组件内部（anatomy、内边距）：组件批准时已在它的 `components.md` 条目里定下，由组件合同测试负责（[screen-conformance.md](screen-conformance.md) §1）。

## 6. Penpot 操作注意

- 写入前确认文件、存版本快照；写完调用 `saveVersion` 并 `await`，再用 `findVersions()` 确认版本确实存在（超时不代表没存上）。
- 每改完一块画板就存一次版本；autosave 曾在重新加载时丢过未保存的改动。
- 字体显示成方块或回退字体是浏览器没加载到字体文件，文件里的字体设置没坏。
- 更多见 [tools/penpot.md](tools/penpot.md)。

## 完成标准

- 值规范里有几何契约；`components.md` 里有 `DS-PAGE-FLOW`，每种关系一个 token，`owner` 行都有决策 id；
- 认可画板校准过，误报都有测试；
- 全部已批准画板扫描干净，记录里有版本标签和规则 commit；
- `AGENTS.md` 写了唯一权威方向和"扫描干净才开工"。
